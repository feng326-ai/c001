# 租户运行时安全地基验收记录（2026-08-23）

## 1. 结论

`TENANT-RUNTIME-ROLE-001` 与 `TENANT-TRANSACTION-AUTH-001` 已通过代码、Compose 契约和 PostgreSQL 15 隔离验收，可以合并到 `main`。本批完成的是尚未接线的运行时安全地基：没有部署 021/022、没有创建或修改已部署数据库角色、没有回填三家公司和成员，也没有让现有 endpoint、页面、Worker 或采集节点进入租户模式。

## 2. 已冻结边界

- Backend、Worker、Beat 只接收显式运行 `DATABASE_URL`；迁移管理连接只进入带 `admin` profile 的一次性 migrate/provision 任务。
- 运行 LOGIN 必须 `NOSUPERUSER NOBYPASSRLS`、非数据库/schema/业务 relation owner、无角色成员关系、无 `public` schema CREATE 权限，且只能读取迁移 ledger。
- 参数化角色工具从环境变量或 `_FILE` 读取管理 DSN、运行角色名与口令，安全引用标识符，支持可重复 provision/check；凭据不进入迁移、Compose 默认值或 Git。
- `tenant_transaction(authenticated_user_id, requested_tenant_id)` 在同一物理连接和事务中重新解析 enabled 用户、设置事务级租户上下文、锁定并校验 active tenant + active membership，之后只暴露不可自行 commit/rollback 的窄事务对象。
- 成功统一提交，失败统一回滚，破损连接淘汰；事务块内禁止调用会另借连接的自治数据库方法，归池连接不得残留租户上下文。
- 选租户前的成员发现只接受服务端已验签 Cookie 对应的 legacy `users.id`，重新解析 `users.public_id` 后调用固定 `search_path`、全限定表名、对 PUBLIC 撤销执行权的窄 `SECURITY DEFINER` 函数。
- 自定义 GUC 只是 RLS 的第二道作用域，不是身份凭据，也不替代应用认证、参数化 SQL 或最小权限角色。

## 3. 隔离 QA 结果

使用 Git 暂存索引生成快照，在局域网 Ubuntu 上以唯一 Compose 项目运行 PostgreSQL 15、Redis 7 与测试容器；未复用测试管理系统或现有生产采集平面的 PostgreSQL、Redis、Celery、网络和数据卷。

- 基础、生产、预发布、QA 四份 Compose 均通过静态渲染；缺运行角色名或口令时契约测试 fail closed。
- 仓库迁移门禁通过：22 个当前迁移连续，SHA-256 基线有效；空库顺序执行 001～022 成功，二次 `--check` 复核 22 条历史成功。
- Ruff fatal gate：通过。
- Pytest：`151 passed`。真实 PostgreSQL 测试使用独立运行 LOGIN，验证角色属性、非所有权、无 schema CREATE、ledger 只读、租户表禁止 DELETE、窄函数授权和真实运行连接。
- 事务矩阵覆盖授权成功、disabled user、inactive tenant/membership、跨租户拒绝、提交/回滚/异常、池复用、线程并发与上下文不残留。

- 测试结束后已核验唯一命名的临时容器、网络、镜像、远程目录和本地暂存快照全部清理。
