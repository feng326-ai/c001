# 租户会话绑定验收记录（2026-08-23）

## 1. 结论

`TENANT-SESSION-BINDING-002` 已通过代码、安全边界、路由契约和 PostgreSQL 15 隔离验收，可以合并到 `main`。本批只交付默认关闭的租户会话边界，没有部署到 Ubuntu 测试管理系统或云端正式环境，没有执行 021/022、没有回填三家公司和用户，也没有开放资源审核业务。

## 2. 已冻结边界

- 保留旧 `wxsess` 的身份和页面兼容行为；新增独立签名、`HttpOnly`、`SameSite=Lax` 的 `wxscope`，并绑定旧登录 Cookie 指纹，租户信息不写入旧 Cookie。
- `wxscope` 只保存服务端可验证的技术声明，不保存公司名、成员角色、团队或业务授权；每个受保护业务请求仍必须进入 `tenant_transaction` 重新核验 enabled user、active tenant 和 active membership。
- 新增 `GET /api/v2/session`、`GET /api/v2/session/tenants`、`PUT /api/v2/session/tenant` 和 `DELETE /api/v2/session/tenant`。bind/unbind 必须校验独立 CSRF 令牌并轮换 scope/CSRF。
- 会话状态明确为 `unbound`、`active`、`stale`、`unmapped`。成员关系被停用或移除后，旧 scope 不继续授权；最后一个 membership 被撤销时返回 stale 并轮换为未绑定 scope。
- `TENANT_SESSION_BINDING_ENABLED`、`TENANT_SESSION_REQUIRED`、`TENANT_REVIEW_ENABLED` 默认均为 false。本版本只允许单独启用 binding；required 或 review 为 true 时启动直接 fail closed，防止误把未完成业务链路开放上线。
- flag 关闭时，新路由统一不可见且不改变旧登录、旧页面、Worker、Beat、采集节点或现有数据库访问行为。登录/退出会按同一 Cookie 属性创建或清理 scope，不遗留跨登录绑定。

- 基础、生产、预发布、QA 四份 Compose 均通过静态渲染；三个功能开关默认关闭，弱密钥、非法布尔值、跳过层级以及提前开启 required/review 均 fail closed。

- Pytest：`193 passed`，覆盖 token 格式/签名/时钟/过期/跨用户/跨登录、CSRF、active/stale/unmapped、inactive membership、统一 404、`tenant_transaction` 调用、Cookie 属性、登录退出、OpenAPI 路由可见性和路径唯一性。

## 4. 发布、回退与剩余风险

本次只合并并推送代码。未来启用必须另开发布批次，先完成三家公司/用户的显式映射、数据库迁移与运行角色落地、预发布演练、备份恢复、逐公司灰度和回退验证；不得从旧 team/role 自动推断租户，也不得直接在正式环境开启 required/review。

当前 `wxscope` 是有时效的无状态令牌，能够在请求时发现 membership 变更，但不能让服务端立即撤销已泄露且尚未过期的旧 `wxsess`。该能力已登记为 `SESSION-REVOCATION-003`，后续用服务端 session 记录与用户 session version 补齐；在此之前，不把本批定义为完整的账户强制下线机制。

资源审核的下一步是 `REVIEW-VERTICAL-SLICE-001`：先建立活动届次、租户资源授权、候选、审核与事务 outbox，并显式区分实时信号和近三年历史回填；CRM/OA 不在该切片内提前耦合。
