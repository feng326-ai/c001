## 二、已建立门禁

- GitHub Actions：PR/push 快速门禁和 PostgreSQL/Redis 真实集成门禁，第三方 Actions 固定到完整 commit SHA，权限仅 `contents: read`；checkout 使用完整历史，PR 对 base SHA、main push 对 previous SHA 执行跨提交门禁。
- Secret：扫描 Git 已跟踪文本和敏感运行时文件名，只输出规则/文件/行号，命中值永不进入日志；`config.json` 停止跟踪但本机文件保留，Docker 构建上下文显式排除；仓库只交付危险功能默认关闭的 `config.example.json`。缺运行时配置、启用态缺显式 Redis 端点或唯一 VM 身份时均 fail closed；配置写回使用原子替换和 Linux 0600，Windows 由发布流程设置最小 ACL。
- 迁移：文件名连续、规范化 UTF-8/LF SHA-256、精确历史 MD5、数据库连续前缀、pending、缺文件、空/非法 checksum 和 drift 均 fail closed；正常 migrate 使用 PostgreSQL advisory lock，`--check` 只读。跨提交比较禁止删除、重命名或修改既有 SQL 与 baseline entry，只允许追加且新版本不得声明 legacy MD5。
- 隔离环境：PostgreSQL 15、Redis 7、内部 Docker 网络、无宿主端口、tmpfs 数据目录、AI/LLM/调度/正式同步硬关闭，测试结束统一销毁。
- 基础测试：`pytest.ini` 固定发现规则和 strict markers，移除放在 `conftest.py` 中从未被收集的假测试。

## 三、迁移历史兼容证据

隔离测试库只读查询得到 018～020 的历史 MD5。按 UTF-8/LF 规范化后：

- 019、020 与当前 SQL 内容一致，先前差异属于工作树 CRLF/LF 的原始字节误报；
- 018 的历史 MD5 是真实已知差异，只接受精确值 `bbaae3b66fb9b6f1fe7be94b46391093`，并同时对 PostgreSQL 15 的完整 `pg_get_viewdef` 做冻结 SHA-256 校验；
- 所有新执行记录统一写 SHA-256，未来迁移不得退化为任意 MD5。

## 五、安全修复边界

- 模型列表探测改为仅 super 可用的 POST；临时 key 在 JSON body，自定义端点必须 HTTPS + 服务端 allowlist，并必须显式提供临时 key，不能继承服务器 key。
- 搜狗日志令牌改 `X-Collect-Token` 请求头；旧 query 默认关闭，仅可在受控滚动升级窗口显式启用并产生告警，节点升级后应删除兼容并轮换令牌。
- 搜狗节点不再要求未使用的 `DATABASE_URL`；LLM 密钥文件支持仓库外路径、0600 和原子写。
- 对话中出现过的 SSH 密码应另开生产变更窗口轮换并迁移到独立 SSH key；本批未擅自修改登录方式。

## 六、剩余风险与下一步

- 运行时依赖仍用宽松 `>=`，镜像/tag/生产挂载的供应链问题进入 `QA-SUPPLYCHAIN-002`。
- 登录/角色、同步 HMAC/重放/乱序、字段所有权与跨租户 RLS 测试进入 `QA-CONTRACT-002`，必须在多租户迁移合并前完成。
- Redis 客户端产生 5 条 `setex` 弃用警告，进入 `CLEANUP-REDIS-SET-003`，不影响本批正确性。
