# 租户映射验收记录（2026-08-23）

## 1. 结论

`TENANT-MAPPING-003` 已通过正式环境只读盘点、严格 manifest 契约、运行角色权限、安全脱敏和 PostgreSQL 15 隔离验收，可以合并到 `main`。本批没有 apply 命令、没有新增迁移、没有生成真实公司/人员清单，也没有部署或写入 Ubuntu 测试管理系统和云端正式数据库。

## 2. 正式环境只读事实

通过云端 PostgreSQL 容器内显式 `BEGIN TRANSACTION READ ONLY`、10 秒 statement timeout 和 `ROLLBACK` 取得的脱敏汇总为：

- 数据库迁移共 20 个，head 为 `020`；021/022 尚未部署。
- `users.public_id`、`tenants`、`tenant_memberships` 均不存在。
- 旧 `teams` 共 5 个；`users` 共 9 个，全部 enabled，1 个用户没有 team，且不存在悬空 team 外键。
- 现状不满足 3 家公司各 1 名审核员 + 8 名销售的 27 个互不重复账号门槛，也不能证明 5 个旧 team 中哪 3 个对应目标公司。

查询未读取密码哈希，没有在对话、日志或仓库中输出用户名和公司名；正式库没有执行 DDL/DML。

## 3. 已交付边界

- production manifest 必须在仓库外、非符号链接、严格 JSON，固定 3 个租户、每租户 8 sales + 1 resource reviewer，27 个一线用户互不重复；platform super 必须显式排除为 `platform_only`。
- 解析器拒绝重复 key、额外字段、非规范 UUID/时间、旧角色冒充租户角色、未知/disabled/遗漏用户、team/public UUID 漂移、跨租户用户、tenant/membership 冲突和数据库快照摘要变化；默认输出不回显公司名、用户名、审批引用或 DSN。
- CLI 只提供 `validate/inventory/dry-run`，不存在 apply，也不接受命令行 DSN。数据库操作强制 READ ONLY、statement timeout、环境匹配和受控全局审计身份，成功或失败一律 rollback、绝不 commit。
- 私有清单同时从 Git 与 Docker build context 排除；仓库只保存合成示例。
- 普通 runtime 对 `tenants/tenant_memberships` 收紧为 SELECT-only；授权在同一连接事务中依次执行已认证 legacy user 查询、022 窄函数精确匹配、成功后 `SET LOCAL tenant`，失败路径不设置 GUC。
- 当前撤权语义是“授权检查完成时取得请求快照，在途事务可收尾，下一事务立即拒绝”。进入资源审核写接口前必须通过 `TENANT-AUTHZ-LOCK-004` 明确是否升级为窄函数行锁语义。
