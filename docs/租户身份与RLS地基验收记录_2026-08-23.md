# 租户身份与 RLS 地基验收记录（2026-08-23）

## 1. 结论

`MIGRATION-TENANT-001` 与 `QA-CONTRACT-002` 第一段通过代码、迁移和 PostgreSQL 15 隔离验收，可以合并到 `main`。本批只是 expand-only、休眠的租户身份地基，不部署迁移、不创建三家公司或成员、不切换旧页面/API/worker，也不代表运行时租户隔离已经上线。

## 2. 本批范围

- 保留 `users.id`、`teams`、旧外键和旧认证路径，仅新增并稳定回填 `users.public_id UUID`。
- 新增 `tenants` 与 `tenant_memberships`，包含冻结的角色、状态、可见策略、版本、时间和唯一/FK/CHECK 约束。
- 新增 fail-closed 的事务租户上下文解析函数；缺失、空值、非法 UUID 均返回 `NULL`。
- 两张新表均 `ENABLE/FORCE ROW LEVEL SECURITY`，策略同时约束 `USING` 与 `WITH CHECK`。
- 不创建授权、候选、审核、商机，不回填三家公司，不启用 `exclusive`。

## 3. 隔离 QA 结果

使用 Git 暂存索引生成只读快照，在局域网 Ubuntu 的唯一命名一次性 Compose 项目中运行 PostgreSQL 15、Redis 7 和测试容器；没有复用测试环境或生产环境的 PostgreSQL、Redis、Celery、网络和数据卷。

- 仓库迁移门禁：21 个当前迁移连续，SHA-256 基线通过，legacy cutoff 保持 020。
- 空库：`db_schema.sql` 后顺序执行 001～021 成功；二次 `--check` 验证 21 条历史成功。
- Ruff fatal gate：通过。
- Pytest：`108 passed`，其中新增的 RLS 测试以临时 `NOSUPERUSER/NOBYPASSRLS`、非表 owner LOGIN 角色执行。
- 越权矩阵：A 租户可读写 A；A 无法读取、更新或伪造写入 B；无/空/非法上下文零行或拒写；同一物理连接提交、回滚后上下文无残留。
- 现有 5 条 Redis `setex` 弃用警告仍在，已作为独立小批次 `CLEANUP-REDIS-SET-003` 登记，不影响本批正确性。
- 测试结束后，唯一命名的临时容器、网络、目录、镜像和本地构建快照均已核验并清理。

## 4. 安全审查与未激活门槛

架构审查确认 021 可以作为 dormant schema 合并，但任何租户 endpoint/worker 或回填启用前必须全部满足：

1. 拆分迁移 owner 与应用运行角色；运行角色必须 `NOSUPERUSER NOBYPASSRLS` 且不是租户表 owner。
2. 实现固定同一物理连接、同一事务的 `tenant_transaction`，授权后只使用事务级 `SET LOCAL`。
3. 服务端以已认证 `users.public_id` 校验 active membership；认证后、选租户前的成员发现只能走最小权限窄入口。
4. 自定义 `app.tenant_id` 只作为 RLS 的二道防误查边界，不能作为身份凭据或抵御数据库连接滥用的安全承诺。

上述工作已登记为 `TENANT-RUNTIME-ROLE-001` 与 `TENANT-TRANSACTION-AUTH-001`。在两项验收完成前，禁止任何应用代码读写 021 新表。

## 5. 发布边界

本次只合并并推送代码，不执行局域网测试系统或云端正式系统数据库迁移。未来部署 021 必须另开发布批次，先完成备份恢复与影子库/预发布演练，再以一次性 migrate job 执行；生产角色、口令和授权不得写入仓库。
