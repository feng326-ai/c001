# 核心领域契约 v1

> **状态**：`v1.0-alpha / structural-frozen`（2026-08-22）。本文件冻结第一批迁移所需的实体边界、主键、幂等键、状态机和字段所有权；原因码、SLA、分配策略等业务可变项仍标为 `pending-business`。在这些待定项确认前可以编写迁移与隔离测试，但不得把临时枚举写死进业务流程。
>
> 本批次只冻结契约，不创建表、不切换现有页面。目标表采用复数 SQL 名；`organizers`、`qualified_leads`、`lead_user_state` 均为 legacy 来源，不直接扩成目标模型。

## 1. 不变量

1. 新业务主键使用 UUID；legacy 自增 ID 只进入映射表。
2. 时间使用 `TIMESTAMPTZ`，API 使用带时区 ISO-8601；可修改聚合带 `version BIGINT` 做乐观并发。
3. 共享事实表不伪造 `tenant_id`；租户通过授权读取共享对象。租户业务表强制 `tenant_id NOT NULL`、索引、服务端作用域与 PostgreSQL `FORCE RLS`。
4. 请求租户来自认证上下文和成员关系，忽略或拒绝请求体/查询参数伪造的 `tenant_id`。
5. 业务记录不硬删除；合并、失效、关闭和重开保留历史与审计。
6. 状态首期使用 `TEXT + CHECK`，不使用难以演进的 PostgreSQL ENUM。
7. 状态变更与事务 Outbox 在同一数据库事务提交；命令必须带 `Idempotency-Key`，更新必须带 `expected_version` 或 `If-Match`。

## 2. 共享情报域

### 2.1 `organizations`（主办方）

| 字段 | 类型/约束 | 语义 |
|---|---|---|
| `id` | UUID PK | 稳定主键 |
| `canonical_name` | TEXT NOT NULL | 当前标准名 |
| `normalized_name` | TEXT NOT NULL, indexed | 匹配辅助，不能作为唯一身份 |
| `identity_key` | TEXT NULL | 经确认的稳定身份键 |
| `organization_type` | TEXT NOT NULL DEFAULT `unknown` | 政府、协会、企业等，字典另版 |
| `region_code/region_name` | TEXT NULL | 地区 |
| `industry_code` | TEXT NULL | 行业字典码 |
| `official_url` | TEXT NULL | 官网 |
| `resolution_status` | TEXT NOT NULL | `proposed/confirmed/merged/tombstoned` |
| `merged_into_id` | UUID NULL FK self | 合并后的 canonical ID |
| `confidence` | NUMERIC(5,4) NULL | 自动解析置信度 |
| `human_verified` | BOOLEAN NOT NULL DEFAULT FALSE | 是否人工确认 |
| `version` | BIGINT NOT NULL DEFAULT 1 | 乐观并发 |
| `created_at/updated_at` | TIMESTAMPTZ NOT NULL | 审计时间 |

约束：

- `identity_key` 仅在非空且 `resolution_status='confirmed'` 时唯一；`normalized_name` 只建索引。
- `merged` 必须有 `merged_into_id` 且不能指向自己；`merged/tombstoned` 为终态。
- 别名进入 `organization_aliases`，建议唯一键 `(organization_id, normalized_alias, source_document_id)`。
- 举办次数不是权威可写列，按已确认的 `organization_event_roles(role='organizer')` 和独立届次生成读模型。

### 2.2 `event_series`（活动系列）

最小字段：

```text
id UUID PK
canonical_name TEXT NOT NULL
normalized_name TEXT NOT NULL
series_key TEXT NULL
activity_category TEXT NULL
recurrence_type TEXT NOT NULL DEFAULT 'unknown'
cycle_months SMALLINT NULL
usual_start_month SMALLINT NULL
next_expected_start DATE NULL
prediction_confidence NUMERIC(5,4) NULL
prediction_as_of DATE NULL
resolution_status TEXT NOT NULL
merged_into_id UUID NULL
version BIGINT NOT NULL DEFAULT 1
created_at/updated_at TIMESTAMPTZ NOT NULL
```

- `recurrence_type`：`annual/biennial/quarterly/monthly/irregular/unknown`。
- `series_key` 仅在已确认且非空时唯一；标准化名称不能唯一。
- `resolution_status`、合并约束和终态语义与 `organizations` 相同。
- 系列可以暂时没有确认周期；主办方关系按届次角色聚合，不在系列表写单一权威主办方。

### 2.3 `event_editions`（活动届次）

```text
id UUID PK
series_id UUID NULL FK event_series
canonical_name TEXT NOT NULL
normalized_name TEXT NOT NULL
edition_key TEXT NULL
edition_year SMALLINT NULL
edition_no INTEGER NULL
activity_category TEXT NULL
region_code/region_name TEXT NULL
activity_stage TEXT NOT NULL DEFAULT 'unknown'
registration_started_at/registration_ended_at TIMESTAMPTZ NULL
voting_started_at/voting_ended_at TIMESTAMPTZ NULL
result_announced_at TIMESTAMPTZ NULL
online_voting_status TEXT NOT NULL DEFAULT 'unknown'
voting_platform TEXT NULL
first_observed_at/last_observed_at TIMESTAMPTZ NOT NULL
resolution_status TEXT NOT NULL
merged_into_id UUID NULL
version BIGINT NOT NULL DEFAULT 1
created_at/updated_at TIMESTAMPTZ NOT NULL
```

状态机：

```text
unknown < planning < nomination < voting < judging < result_published < ended
任意非终态 → cancelled
```

- 上式表示顺序而非必须相邻转换；首次发现可以从 `unknown` 直接进入任意更晚阶段。自动处理只能单调向前跳转；历史乱序证据可以补阶段时间，不能自动倒退当前阶段。人工纠错允许逆向，但必须记录原因和审计。
- `online_voting_status`：`unknown/suspect/has/none`。
- `edition_key` 仅在已确认且非空时唯一；标题、年份或 legacy `event_key` 不能单独强制唯一。
- `event_sources(event_edition_id, source_document_id)` 唯一。
- `resolution_status`、合并约束和终态语义与 `organizations` 相同。
- `organization_event_roles(event_edition_id, organization_id, role, source_document_id)` 唯一；`role` 冻结为 `organizer/co_organizer/undertaker/co_undertaker/advisor/supporter`，分别表示主办、联合主办、承办、联合承办、指导和支持，禁止使用歧义 `host`。举办次数只统计 `organizer/co_organizer`，是否把联合主办计为完整一次由读模型口径版本控制。
- 候选、审核和商机必须引用具体届次，不能只引用系列。

### 2.4 实体裁决与字段保护

`entity_resolution_decisions` 最小字段：

```text
id UUID PK
entity_type TEXT NOT NULL                 # organization/event_series/event_edition
source_entity_id UUID NOT NULL
decision_type TEXT NOT NULL               # confirm/merge/split/tombstone/correct
target_entity_id UUID NULL
child_entity_ids UUID[] NULL              # split 时使用
evidence_assignment JSONB NOT NULL DEFAULT '{}'
reason_code/reviewer_note TEXT NULL
decided_by UUID NOT NULL
decision_version BIGINT NOT NULL
occurred_at TIMESTAMPTZ NOT NULL
```

同一实体的 `decision_version` 单调递增。merge 产生重定向；split 必须 tombstone 原 ID 并显式记录子实体与证据分配；后续歧义证据进入复核队列。

`entity_field_provenance` 冻结字段级自动建议与人工裁决，最小字段为：`entity_type/entity_id/field_name/value_json/source_type/source_evidence_id/confidence/is_human_locked/is_current/effective_at/superseded_at/version`。部分唯一索引保证 `(entity_type,entity_id,field_name) WHERE is_current=true` 只有一行；替换当前值时在同一事务把旧行置 `is_current=false` 并写 `superseded_at`。人工锁定后，上游同步只能追加非当前自动建议，不能覆盖 canonical 值。主表保存当前投影，provenance/decision 是冲突裁决依据，禁止仅按 `updated_at` 争抢。

## 3. 租户地基

### 3.1 `tenants` 与 `tenant_memberships`

`tenants` 最小字段：`id UUID PK`、`code TEXT UNIQUE`、`name TEXT`、`status active/disabled`、`default_visibility_policy shared_competition/...`、`version`、审计时间。该字段只是新授权的默认值，具体资源的权威策略始终保存在 `tenant_resource_grants.policy`。

现有 `users.id INTEGER` 在 expand 阶段新增 `public_id UUID UNIQUE NOT NULL DEFAULT gen_random_uuid()`，保留整数主键和所有旧外键；所有 v2 API、事件和新租户表只使用 `users.public_id`，并通过 `(legacy users.id, public_id)` 做稳定映射，不新建平行身份表。

`tenant_memberships` 最小字段：`id UUID`、`tenant_id UUID`、`user_id UUID FK users(public_id)`、`role`、`status`、审计时间；有效成员唯一键 `(tenant_id, user_id)`，并额外提供该组合唯一约束供 Review/Opportunity 组合外键引用。首期租户角色为 `tenant_admin/resource_reviewer/sales/readonly_manager`。当前每公司 1 名审核员、8 名销售是初始化数据，不做人数上限约束。

### 3.2 `tenant_resource_grants` 与 `tenant_candidates`

采用“授权历史多行 + 单一有效授权”模型：

```text
tenant_resource_grants:
  id UUID PK
  tenant_id UUID NOT NULL
  event_edition_id UUID NOT NULL
  policy TEXT NOT NULL
  policy_version TEXT NOT NULL
  status TEXT NOT NULL                 # active/revoked/superseded
  grant_source TEXT NOT NULL
  granted_at TIMESTAMPTZ NOT NULL
  revoked_at TIMESTAMPTZ NULL
  supersedes_grant_id UUID NULL
  version BIGINT NOT NULL DEFAULT 1
  created_at/updated_at TIMESTAMPTZ NOT NULL

tenant_candidates:
  id UUID PK
  tenant_id UUID NOT NULL
  grant_id UUID NOT NULL
  event_edition_id UUID NOT NULL
  candidate_status TEXT NOT NULL       # open/in_review/closed/withdrawn
  score NUMERIC(8,4) NULL
  score_version TEXT NULL
  generated_at TIMESTAMPTZ NOT NULL
  version BIGINT NOT NULL DEFAULT 1
  created_at/updated_at TIMESTAMPTZ NOT NULL
```

- 授权使用部分唯一索引 `UNIQUE(tenant_id,event_edition_id) WHERE status='active' AND revoked_at IS NULL`；撤销/替换追加新历史，不原地抹除旧授权。
- Candidate 对 `(tenant_id,event_edition_id)` 永久唯一，重新开放复用同一 Candidate 并新增审核轮次，不因策略版本生成重复工作项。
- 组合外键保证 Candidate 的 `tenant_id/event_edition_id` 与 Grant 一致。撤销授权不能静默删除已开始的审核或商机，后续动作由显式业务规则处理。
- Candidate 创建为 `open`；首轮开始变为 `in_review`；审核完成变为 `closed`；只有 `closed` 可重新开放并再次进入 `in_review`。`open/closed → withdrawn` 只用于授权撤销且不存在活跃审核/商机的显式操作，`withdrawn` 不自动恢复。

当前策略为 `shared_competition`：同一公开届次可为三家公司各创建授权和候选。预留 `tenant_private/selected_tenants/exclusive`，未确认商业规则前不得启用 `exclusive`。

## 4. `tenant_reviews`（资源审核）

```text
id UUID PK
tenant_id UUID NOT NULL
candidate_id UUID NOT NULL
event_edition_id UUID NOT NULL
grant_id UUID NOT NULL
grant_policy_version TEXT NOT NULL
review_round INTEGER NOT NULL DEFAULT 1
review_status TEXT NOT NULL
review_decision TEXT NULL
disposition TEXT NULL
reason_code TEXT NULL
reason_schema_version TEXT NULL
field_overrides JSONB NOT NULL DEFAULT '{}'
reviewer_note TEXT NULL
reviewer_user_id UUID NULL
ai_assessment_id UUID NULL
rule_version TEXT NULL
started_at/completed_at TIMESTAMPTZ NULL
supersedes_review_id UUID NULL
version BIGINT NOT NULL DEFAULT 1
created_at/updated_at TIMESTAMPTZ NOT NULL
```

状态与规则：

```text
review_status:   pending → in_review → completed
review_decision: qualified | rejected | needs_more_info
disposition:     sales_handoff | nurture | competitor_watch | archive
```

- 唯一键 `(tenant_id,candidate_id,review_round)`；同一候选最多一个 `pending/in_review` 审核。
- `grant_id/grant_policy_version` 是创建该轮审核时的授权快照；Candidate 后续引用新授权不能改写历史 Review 的依据。
- `completed` 后决定、去向、审核人和完成时间必填；已完成审核不可原地覆盖，重新审核创建下一轮并关联 `supersedes_review_id`。
- Candidate、Review 和 Edition 必须通过组合外键/事务断言保持租户和届次一致。
- `(tenant_id,reviewer_user_id)` 必须引用同租户有效成员，不能把其他公司用户挂为审核人。
- `field_overrides` 只改变本租户视图，允许字段由版本化 JSON Schema 白名单控制；共享事实纠错进入 `data_correction_requests`。
- 临时决定/去向矩阵为：`qualified → sales_handoff/nurture/competitor_watch`，`rejected → archive/competitor_watch`，`needs_more_info → nurture`。该矩阵与原因码为 `pending-business`，编码前确认。

## 5. `opportunities`（商机）

```text
id UUID PK
tenant_id UUID NOT NULL
event_edition_id UUID NOT NULL
organization_id UUID NULL
source_review_id UUID NULL
previous_opportunity_id UUID NULL
owner_user_id UUID NULL
stage TEXT NOT NULL
priority TEXT NULL
first_contact_due_at/first_contacted_at TIMESTAMPTZ NULL
next_follow_up_at TIMESTAMPTZ NULL
next_action TEXT NULL
estimated_value/won_value NUMERIC(14,2) NULL
currency CHAR(3) NOT NULL DEFAULT 'CNY'
close_reason_code TEXT NULL
closed_at TIMESTAMPTZ NULL
version BIGINT NOT NULL DEFAULT 1
created_at/updated_at TIMESTAMPTZ NOT NULL
```

阶段：

```text
unassigned → pending_contact → contacted → qualification → qualified
           → proposal → quoted → won | lost
pending_contact/contacted/qualification/qualified/proposal/quoted → deferred
deferred → pending_contact
```

- `qualified + sales_handoff` 完成审核时，在同一事务幂等创建 `unassigned` 商机。
- `UNIQUE(tenant_id,source_review_id) WHERE source_review_id IS NOT NULL`，保证一次交接只创建一次。
- `UNIQUE(tenant_id,event_edition_id) WHERE closed_at IS NULL`，保证公司内部同届只有一个活跃商机；不同租户之间允许竞争。
- `won/lost` 必须有 `closed_at`；`lost` 必须有原因码。关闭后重开会创建新商机并填写 `previous_opportunity_id`，不改写关闭记录。
- `(tenant_id,owner_user_id)` 必须引用同租户有效成员且成员具备销售/管理权限。
- 今日待联系、再次联系、已超时由负责人和时间派生，不是阶段。
- 分配、转交、电话、消息、备注、提醒、阶段变化进入只追加的 `opportunity_activities`；关闭结果进入 `opportunity_outcomes`。

## 6. 字段所有权与同步

| 数据 | 权威写入方 |
|---|---|
| 原始来源、自动抽取建议、共享 AI 结果 | 本地采集/智能平面 |
| 主办方/系列/届次人工确认、合并、拆分、tombstone | 云端平台数据管理员 |
| 授权、候选、租户覆盖、审核、商机、联系活动、报价、结果 | 云端对应租户 |
| 租户匹配评分 | 云端对应租户 |
| 全局实体解析控制事件 | 云端平台数据管理域；版本化回传本地 |

自动建议与人工裁决不能靠“最后更新时间”竞争。可人工修订字段必须保留来源、证据、置信度和人工锁定状态；上游只能更新自动建议，不能覆盖人工值或任何租户 CRM 字段。

当前 `production_sync_outbox` 只接受 `article/lead`。新领域事件必须先冻结 v2 接收端、扩展 CHECK 和契约测试，不能塞入旧 `lead` payload。

## 7. API 与事件最小契约

第一批资源路径：

```text
GET  /api/v2/organizers
GET  /api/v2/organizers/{id}
GET  /api/v2/event-series
GET  /api/v2/event-series/{id}
GET  /api/v2/event-editions
GET  /api/v2/event-editions/{id}
GET  /api/v2/event-editions/{id}/sources
POST /api/v2/data-correction-requests
GET  /api/v2/tenant-candidates
POST /api/v2/tenant-candidates/{id}:start-review
POST /api/v2/tenant-reviews/{id}:complete
POST /api/v2/tenant-candidates/{id}:reopen-review
GET  /api/v2/opportunities
POST /api/v2/opportunities/{id}:assign
POST /api/v2/opportunities/{id}:transition
POST /api/v2/opportunities/{id}/activities
POST /api/v2/opportunities/{id}:close
POST /api/v2/opportunities/{id}:reopen
```

Candidate 创建时不预建空 Review；`:start-review` 仅允许 `open` 且从未审核的 Candidate，在同一事务创建第一轮 `in_review` 并把 Candidate 置 `in_review`。`:reopen-review` 仅允许 `closed` Candidate，创建下一轮并重新置 `in_review`。完成 Review 后 Candidate 置 `closed`。跨租户资源按“不暴露存在”处理；版本冲突返回 409，非法状态转换返回 422。商机 `:reopen` 返回新商机，不修改旧关闭记录。

统一事件信封：

```json
{
  "message_id": "uuid",
  "event_type": "review.completed.v1",
  "schema_version": "1.0",
  "aggregate_id": "uuid",
  "aggregate_version": 3,
  "tenant_id": "uuid-or-null",
  "occurred_at": "ISO-8601",
  "correlation_id": "uuid",
  "causation_id": "uuid-or-null",
  "payload": {}
}
```

公共事件 `tenant_id=null`；租户事件必须携带服务端确认的租户。消费者按 `message_id` 幂等，按 `aggregate_version` 拒绝乱序回退，payload 只含最小字段和引用。

事件目录与方向冻结如下：

| 方向 | 事件 |
|---|---|
| 本地智能平面 → 正式共享域 | `organizer.suggested.v1`、`event_series.suggested.v1`、`event_edition.suggested.v1`、`event_evidence.linked.v1`、`ai_assessment.completed.v1` |
| 正式共享域 → 本地智能平面 | `entity_resolution.decided.v1` |
| 正式租户域内部/对 OA | `candidate.created.v1`、`review.completed.v1`、`opportunity.created.v1`、`opportunity.assigned.v1`、`opportunity.stage_changed.v1`、`opportunity.closed.v1` |

## 8. Legacy 映射与迁移次序

| Legacy | 目标 | 首次处理 |
|---|---|---|
| `articles_core` | `source_documents` | 保留映射、稳定 UUID/哈希 |
| `qualified_leads` | `event_editions` + AI 结果 | 一对一种子后再离线聚合，不能直接视为已确认届次 |
| `organizers` | `organizations` + 别名/角色 | `norm_key` 只作候选，不自动作为唯一身份 |
| `teams`/用户 | `tenants`/memberships | 先冻结三家公司和用户正式映射 |
| `lead_user_state` | 反馈样本/个人偏好 | 不自动生成已完成审核或权威商机 |

实施顺序：保护网 → expand-only 租户/RLS → 共享实体 → 审核/商机 → 保守回填 → 影子写读与对账 → 单租户 canary → 逐聚合切权威。任何阶段不删除旧表。

## 9. 发布阻断门禁

- 空库与脱敏快照两条升级路径最终 schema 一致；迁移 checksum 漂移有精确基线和最终态断言。
- 所有租户表验证 `tenant_id NOT NULL`、外键/索引、`ENABLE/FORCE RLS`；A 可读写 A、不能读写 B，伪造 `tenant_id` 无效，连接池复用无上下文残留。
- 重复命令/事件不重复建候选、审核轮次、活跃商机或调用模型；乱序事件不能回退状态。
- 现有采集、LLM 唯一执行方、正式同步和旧页面均可回归；切换有开关和对账水位。

## 10. `pending-business`

以下问题不阻塞结构迁移和 RLS 测试，但会阻塞对应工作流上线：

1. “近三年”是滚动 36 个月，还是当前自然年加前两个自然年。
2. Review 原因码字典及 `decision × disposition` 最终矩阵。
3. 商机由业务员领取、审核员/经理分配还是负载自动分配，以及首审、首联、回收 SLA。
4. `won` 的确认口径、成交金额是否必填，以及 `lost/deferred` 原因码；关闭后重开已经冻结为创建关联的新商机。
5. 三家公司、用户、历史个人状态的正式租户映射清单。
