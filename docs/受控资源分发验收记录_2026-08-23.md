# 受控资源分发验收记录（2026-08-23）

## 结论

`REVIEW-DISTRIBUTOR-002` 的代码与隔离 QA 验收通过。系统现在具备默认关闭的“受信 Inbox → 冻结租户 Target → 单 Target 租约与 fencing → Grant/Candidate/Outbox 原子提交”能力，但没有部署、没有真实租户设置、没有真实 Inbox writer，也没有接入 HTTP 或 Celery。

## 本批交付

- 迁移 025：平台控制域中的租户设置、不可变 Inbox、批次与 Target 状态机。
- 四个窄数据库入口：展开、领取、应用、失败上报；均固定 `search_path`、全限定对象并撤销 PUBLIC。
- 独立 Distributor LOGIN 的配置、创建与核验工具；角色非 owner、非 super、`NOBYPASSRLS`，不持有业务表和控制表直接权限。
- 默认关闭的 Python 服务层；公开方法不接受租户列表、策略、来源模式或评分。
- 冻结契约、迁移 checksum、单元/静态契约与 PostgreSQL 15 集成测试。

## PostgreSQL 15 实证

一次性数据库从 `db_schema.sql` 顺序执行 001～025，并再次以 `--check` 只读核对 25 个版本。随后以独立普通运行角色、独立 Distributor 角色和管理测试身份验证：

- 普通运行角色不能执行分发入口；Distributor 不能直接读取控制表或业务表，只直接获得四个精确函数，且有效可执行的应用域 `SECURITY DEFINER` 集合严格等于这四个。历史 PUBLIC `SECURITY INVOKER` 辅助函数不构成表访问能力。
- 历史回填 Inbox 被拒绝且不创建 Batch、Target、Grant 或 Candidate。
- 三个显式批准且具备 active ruleset 的共享竞争租户各生成一个冻结 Target；禁用租户和缺少 activation 的租户不进入计划。
- 每个 Target 冻结设置版本、审批引用、资格版本和 ruleset 快照；设置只允许一次性 `enabled → disabled` 撤销，旧行不能复活。
- 同一 Inbox 8 路并发展开只产生一个 Batch 和三个 Target；一个首次结果，其余均为幂等 replay。
- Target 冻结后撤销某租户资格，apply 会再次锁定并校验，目标安全跳过；两个仍合格租户正常完成，Batch 投影为 completed。
- 过期租约可被重新领取，新 token 替代旧 token；旧 token 的迟到 apply 被拒绝。
- 人工注入单一租户 Candidate 写失败时，该租户 Grant/Candidate/Outbox 全部回滚，其余两个租户独立提交；失败上报后可受控重试成功。
- 已撤销 Grant/withdrawn Candidate 不被重新授权或复活，进入 `blocked_regrant_required`。
- 首次成功创建 Grant、Candidate、`candidate.created.v1` Outbox 和 Target succeeded 在同一事务内完成；重复路径不重复发事件。
