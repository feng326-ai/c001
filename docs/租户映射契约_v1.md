# 租户映射契约 v1

## 1. 目的与当前事实

本契约用于把旧 `teams/users` 中的人员，经过公司逐家确认后，显式映射到 `tenants/tenant_memberships`。它不把旧字段升级为租户授权来源，也不提供生产写入命令。

2026-08-23 对云端正式库的只读事务盘点结果为：迁移历史停在 020；`users.public_id`、`tenants`、`tenant_memberships` 尚不存在；旧 `teams` 为 5 个，`users` 为 9 个且全部 enabled，其中 1 个账号无 team。该事实与“3 家公司、每家 1 名资源审核员 + 8 名销售”的 27 个一线账号上线目标不一致，因此当前没有可批准的正式映射清单，021/022 与租户功能开关均不得据此启用。

## 2. 私有 manifest

正式 manifest 是仓库外受限文件。Git 只保存合成示例，不保存真实公司名、用户名、审批人姓名或人员归属。production manifest 位于仓库内、是符号链接、含重复 JSON key、未知字段或非规范值时，工具必须拒绝。

顶层字段：

- `schema_version`：固定为 `1`。
- `batch_id`：本批稳定 UUID，重跑不得变化。
- `target_environment`：`production/staging/qa/example` 之一。
- `source_snapshot_at`：带时区时间。
- `source_users_digest_sha256`：目标库按 ID 排序的 `(id, public_id, username, enabled, role, team_id)` 规范化快照摘要；用户名只参与本地摘要，不进入默认报告。
- `approval_reference`：仓库外审批记录引用。
- `policy`：期望租户数、每租户销售/审核人数以及 `allow_cross_tenant_users=false`。production v1 固定为 `3/8/1/false`。
- `tenants`：逐家公司确认的租户与成员。
- `excluded_users`：显式分类为 `platform_only/legacy_only/suspended` 的非租户账号。所有 enabled 用户必须在成员或排除列表中且只出现一次。

租户字段：稳定 `tenant_id`、规范 `tenant_code`、私有 `tenant_name`、`default_visibility_policy=shared_competition`、`initial_status=disabled`、一个 `observed_legacy_team_id`、期望人数、公司审批引用和 `memberships`。

成员字段：稳定 `membership_id`、`legacy_user_id_observed`、`user_public_id`、`legacy_team_id_observed`、`legacy_role_observed`、显式 `tenant_role`、`membership_status=active`、`mapping_action=create|keep`、原因码和公司审批引用。旧 `member/admin/super` 不得作为 `tenant_role`；首期 production 一线账号只允许 `resource_reviewer/sales`，平台 super 必须在排除列表中且为 `platform_only`。

## 3. 校验和 dry-run

仓库工具只提供：

```text
validate  离线严格解析并输出 manifest SHA-256 与脱敏计数
inventory 以 READ ONLY 事务输出迁移版本、表就绪度、用户/团队计数和用户快照摘要
dry-run   以 READ ONLY 事务比较 manifest 与数据库，输出稳定的 would-create/no-op/阻断计数
```

工具不存在 `apply` 子命令，不接受 DSN 命令行参数。连接只从 `TENANT_MAPPING_DATABASE_URL` 或 `_FILE` 读取；`TENANT_MAPPING_TARGET_ENVIRONMENT` 必须与 manifest 一致。事务必须为 `READ ONLY`，设置 statement timeout，成功或异常一律 rollback、绝不 commit。dry-run 还必须使用能够完整审计 FORCE RLS 身份表的受控管理身份，普通 runtime 的“零行可见”不能被误判为“全部待创建”。

下列情况统一 fail closed：021/022 未完成，目标环境或用户摘要不匹配，未知/disabled 用户，legacy ID 与 public UUID 不属于同一用户，team 观察值变化，tenant UUID/code 冲突，重复 membership，跨租户用户，super 成员，角色/状态非法，遗漏 enabled 用户，已有对象与清单漂移，或存在清单之外的目标租户 membership。错误不得回显用户名、公司名、DSN 或清单原值。

## 4. 发布顺序

1. 业务负责人先确认正式 5 个旧 team 中哪 3 个代表三家公司，并补齐/核对 27 个一线账号；不得按 team 或旧 role 自动生成。
2. 另开发布批次完成备份恢复演练，部署 021/022、运行角色和预发布验证；tenant identity 表对普通 runtime 必须是 SELECT-only。
3. 重新生成含 `public_id` 的私有快照，各公司只核对本公司 roster，平台汇总并确认 manifest SHA-256。
4. production dry-run 必须零阻断、人数为 `3 × (8 sales + 1 resource_reviewer)`、platform super 零 membership。
5. 未来独立 apply 批次使用 migration owner，在单事务内按精确已批准 SHA 幂等创建 disabled tenant 和 active membership；已有状态不同则中止，不静默覆盖或删除。
6. 对账、RLS 正反向测试和 Session 撤销通过后，逐公司 canary 激活；`TENANT_SESSION_REQUIRED` 与审核开关继续后置。

映射不会修改 `users.team_id/role`。旧入口新增或调整用户时先进入未映射队列；在 v2 用户管理命令完成前，不使用 trigger 自动双写 team 与 tenant。
