# 审核规则集契约 v1

> 规则版本：`review-rules/1.0.0`。状态：代码与隔离数据库验收阶段；生产审核开关保持关闭。本文冻结资源审核原因、矩阵、优先级和重审规则，冲突时以《核心领域契约 v1》和 D-035 为准。

## 1. 不变量

- 规则内容与租户激活分离；一个租户同一时刻最多一个 active 规则版本。
- 规则发布后不可修改或删除；新口径发布新版本。
- start/reopen 由服务端读取并锁定 active 规则，在 Review 保存版本、SHA-256 和 JSON 快照。
- complete 只使用 Review 快照。客户端提交的规则版本、摘要、priority 或完整 snapshot 一律拒绝。
- 原因码是稳定机器码；中文标签可以新增展示翻译，但不能改变代码语义。
- 完成审核必须且只能有一个主原因码；备注不得进入跨服务公共事件。

## 2. 决定、去向与主原因

| 原因码 | decision | disposition | 附加门禁 |
|---|---|---|---|
| `sales_ready_confirmed` | `qualified` | `sales_handoff` | 需要 `opportunity_atomic_create`；当前固定拒绝 |
| `future_contact_window` | `qualified` | `nurture` | 必填未来 `reopen_not_before` |
| `valid_but_not_sales_ready` | `qualified` | `nurture` | 必填未来 `reopen_not_before` |
| `competitor_present_replaceable` | `qualified` | `competitor_watch` | 必填未来 `reopen_not_before` |
| `not_selection_or_voting` | `rejected` | `archive` | 无 |
| `event_ended_or_too_late` | `rejected` | `archive` | 无复办/再联系价值时使用 |
| `no_online_voting_need` | `rejected` | `archive` | 必须有明确否定证据，不能把 unknown 当 none |

除表内组合外全部返回 422 且业务表、receipt、outbox 零写。`qualified` 不等于已经创建商机；只有 `qualified + sales_handoff` 且商机与审核同事务成功才形成销售交接。

## 3. 再评时间

- `nurture`、`competitor_watch` 必须提供带时区时间，并且晚于数据库当前时间。
- `archive`、`sales_handoff` 不接受 `reopen_not_before`。
- 时间只是允许重审的最早门槛，不自动重开、不自动改变 decision。
- 前端应显示到期条件；任务生成和 SLA 告警由后续 OA 批次实现。

## 4. 重审

API 使用 `POST /api/v2/tenant-candidates/{candidate_id}:reopen-review`，请求携带上一轮 Review、Candidate/Review 期望版本、重审原因和可选触发来源。

允许原因：

| 原因码 | 门禁 |
|---|---|
| `scheduled_recheck_due` | 前轮 `reopen_not_before` 已到；不要求新来源 |
| `new_realtime_evidence` | 必须引用前轮完成后新关联的 realtime 来源 |
| `missing_information_resolved` | 必须引用前轮完成后新关联的 realtime 来源 |
| `competitor_status_changed` | 必须引用前轮完成后新关联的 realtime 来源 |

同时必须满足：原 Grant active、Candidate closed、指定 Review 是该 Candidate 最新 completed 轮次、当前无 active Review、轮次小于 3、resource reviewer、双 expected version 和合法 Idempotency-Key。重审取当时本租户 active 规则版本，创建 round N+1 并关联 `supersedes_review_id`；旧 Review 字节级不变。规则版本或分数变化本身不是重审理由。

## 5. 优先级排序输入契约

本版本冻结的是 `review-priority-envelope/1.0.0` 排序输入 envelope，不是可从原始证据自动复算的业务评分 rubric。快照必须独立保存该 method version；五个 component 只接受规则版本内列举的 explanation code。具体分桶、证据到分数的确定性映射和 scorer producer 版本在后续业务标定批次冻结，在此之前只允许受控离线评估写入，不得宣称为自动智能评分。

| component | 上限 | 含义 |
|---|---:|---|
| `timeliness_stage` | 30 | 时效与当前活动阶段 |
| `online_voting_demand` | 25 | 线上评选/投票需求证据 |
| `organizer_value` | 20 | 主办方价值、复办与历史届次 |
| `contactability` | 15 | 公开联系方式的可达性和新鲜度 |
| `evidence_quality` | 10 | 来源可信度、多源一致性和信息完整度 |

允许的解释码按 component 固定：

- `timeliness_stage`：`timeliness_unknown`、`timeliness_historical`、`timeliness_future`、`timeliness_active`、`timeliness_urgent`。
- `online_voting_demand`：`demand_unknown`、`demand_negative`、`demand_indirect`、`demand_explicit`。
- `organizer_value`：`organizer_unknown`、`organizer_first_seen`、`organizer_repeat`、`organizer_strategic`。
- `contactability`：`contact_none`、`contact_stale`、`contact_indirect`、`contact_verified`。
- `evidence_quality`：`evidence_weak`、`evidence_single_source`、`evidence_correlated`、`evidence_verified`。

总分为五项之和且只能在 0～100。每项保存 score 与规则内白名单 `explanation_code`；明确否定不能用“unknown”解释码。不可变 score snapshot 还保存 evidence refs、input hash、as-of、规则版本、SHA-256 和独立 `scoring_method_version`。相同规则版本不代表不同 scoring method 可混为同一输入；在 rubric 冻结前，快照只支持排序和审计，不保证从 evidence refs 自动复算。

| band | 分数 | 审核目标 |
|---|---:|---|
| `urgent` | 80～100 | 2 小时内开始审核 |
| `high` | 60～79.99 | 当前工作日 |
| `normal` | 40～59.99 | 24 小时 |
| `low` | 0～39.99 | 每日限额探索，不挤占高优先级 |

评分仅排序，不自动完成、拒绝、分发或创建商机。没有可验证 snapshot 的候选显示 `unscored`，不能把 legacy score 冒充本规则版本评分。

## 6. 幂等与事件

- 同租户、同命令、同 key、同规范请求重放，返回首次保存的 Review、message 和规则快照标识。
- 同 key 改目标、期望版本、原因、时间或来源返回 409。
- 首次命令的规则校验失败必须回滚 receipt；已经成功的命令即使 activation 后来切换，仍可按同 key 重放首次响应。
- `review.completed.v1` 增加 `rule_version`、`reason_code` 和可空 `reopen_not_before`，不含 reviewer note。
- 重审同事务写入 `review.reopened.v1`；Review、Candidate、outbox 和 receipt 要么全部提交，要么全部回滚。

## 7. 启用和回滚

迁移 024 只种下不可变规则版本，不为任何真实租户自动创建 activation。activation 必须由以后受控管理身份逐租户写入，运行角色无写权限。

本批完成后生产开关仍保持关闭。回滚代码时不删除 024 对象；停止使用新入口即可。规则回滚新增/切换 activation 指针，禁止 UPDATE 规则正文或 completed Review。
