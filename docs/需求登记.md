## 🔲 待做

### 第二期：私有关键词（PRIVATE KEYWORDS）
**状态**：需求已对齐，待实施。

**目标**：用户自己加的关键词，采集结果只对自己展示；混进公海列表并打「私有」标。

**已对齐决策**：
1. **归属**：个人私有——谁加的词，结果只给他本人看，团队其他人也看不到。
2. **展示位置**：私有词产出的线索**混进公海列表**，用「私有」标签区分（不单独开页）。
3. **采集配额**：先不限制（私有词与全局词一起排队采集）。
4. **可见性规则**：
   - 一条线索**被任一全局词命中** → 进公海（所有人可见）。
   - 一条线索**仅被某人的私有词命中** → 只对该归属者可见。
   - 判定依据：`keyword_article_map`（一篇可被多词命中）。
5. **采集**：私有词照常进分布式调度，可分配搜狗/搜一搜渠道。

**技术要点（拟）**：
- `keywords` 加 `owner_user_id`（NULL=全局）+ `visibility`（global | private）。
- 线索列表查询增加可见性过滤：`命中全局词 OR 命中我的私有词`。
- 列表对「仅私有词命中」的线索渲染「私有」标。
- 关键词管理页：加「归属（全局 / 我的私有）」，成员可增删自己的私有词。
- 迁移：现有关键词全部标为 `global`。

### 人在回路（Human-in-the-Loop）自学习闭环
**状态**：需求已对齐，阶段A 立即做，B/C/D 后续。

**目标**：业务反馈反向喂给系统，使其越用越聪明。三级闭环映射到本系统：
- 第1级 负向黑名单 = 入库规则评分器（新增负向词表，命中直接丢，省 LLM）
- 第2级 门禁(Hard Negative) = rule_config.thresholds.lead_min_score 晋级关口 + 硬负样例
- 第3级 Few-Shot 正样例 = LLM 提示词 prompt_schemas 里的正样例（维护 Top-N 轮换）

**反馈信号源**：现有 收藏(正)/赞(正)/回收站(负)/反对(负)/已处理；未来 CRM/OA「成单/转化」为最强信号（并入第三期）。

**已对齐决策**：
1. **半自动 + 人工复核**：反馈→自动出候选（候选黑名单词/候选正样例）→超管在「反馈复盘」面板一键采纳/忽略→生效。绝不全自动改规则（防误杀/漂移/被单人口味带偏）。
2. **先做阶段A（地基）**。

**分阶段**：
- **A 地基（现在做）**：反馈样本聚合（跨用户聚合 收藏/赞/回收站/反对）+ 超管「反馈复盘」面板（正/负样本两栏 + 计数 + 特征展示），只读复盘、不改规则。
- **B 负向闭环**：负向黑名单表 + 入库前置过滤 + 负样本挖候选词→人工采纳。
- **C 正向闭环**：Few-Shot 正样例池 + 优质样本→候选→人工采纳进提示词。
- **D CRM 信号**：OA/CRM 转化结果回流，最强正/负信号（并入第三期）。

**风险**：自动特征提取仅作候选建议(人拍板)；反馈稀疏需先攒数据；按多人/团队聚合防偏差；Few-Shot 固定池防提示词膨胀。

### 第三期：OA 系统对接（只读）
**状态**：待 OA 需求明确后细化。

**已对齐方向**：
- 系统保持独立，**OA 只消费我们的数据库**（不侵入本系统应用）。
- 大概率方式：**只读数据库视图**（建稳定对外字段契约的视图 + 只读账号 + 增量拉取），而非直连内部表。
- 个人状态因人而异，OA 通常取「线索本体 + 处理情况聚合」，视图设计到时再定。
- CRM/OA 的「成单/转化」结果回流，作为人在回路的最强正/负信号。
