# 租户会话绑定契约 v1

## 1. 目标与非目标

本契约在不改变旧 `wxsess` 登录会话、`team_id` 页面和 v1 API 的前提下，为未来租户业务提供显式的“认证后、选租户”入口。当前只负责租户发现、绑定、解绑和作用域解析；不让旧公海变成租户页面，不创建三家公司/成员，不开放审核、CRM 或 OA。

租户作用域 Cookie 只是一个经服务端签名的候选 tenant。它不是数据库授权凭据，也不能替代每个业务命令中的 `tenant_transaction`。

## 2. 开关与激活顺序

| 开关 | 默认值 | 含义 |
|---|---:|---|
| `TENANT_SESSION_BINDING_ENABLED` | `false` | 开放 `/api/v2/session*` 的 discovery/bind/unbind |
| `TENANT_SESSION_REQUIRED` | `false` | 未来要求租户页面必须已绑定；本批禁止开启 |
| `TENANT_REVIEW_ENABLED` | `false` | 未来资源审核入口；本批禁止开启 |

依赖顺序固定为 binding → required → review。任何非法布尔值、跳级开启、binding 使用弱/占位 `SESSION_SECRET`、非法 Cookie/TTL 配置都必须在应用启动时失败。关闭 binding 时 v2 session 路由返回 404，旧登录和旧页面不读取 `wxscope`。

## 3. Cookie 契约

- 旧 `wxsess` 格式保持 `uid.issued_at.HMAC`，仍是用户认证来源。
- 新 `wxscope` 为 `v1.user_id.auth_fingerprint.session_id.tenant_id|-.issued_at.expires_at.HMAC`。
- `auth_fingerprint` 绑定当前原始 `wxsess`；A 用户、旧登录或不同浏览器的 scope 不能套用到另一登录。
- `session_id` 是每次登录/绑定/解绑重新生成的 128 bit 随机值，用于轮换 CSRF token。
- Cookie 不保存 `users.public_id`、membership id/role、`team_id`、租户名称或权限。
- 两个 Cookie 均使用 `HttpOnly + SameSite=Lax + Path=/`；production/staging 必须 `Secure`。
- scope 拒绝超长、字段数量错误、非规范 UUID、非法 session id、错误签名、跨用户、跨登录、负/超前签发时间、异常 TTL 和过期 token。

本批无状态 Cookie不能做到服务端单会话撤销；logout 只能清除浏览器 Cookie。未来 `SESSION-REVOCATION-003` 应引入只存 token hash 的 `user_sessions` 与 `users.session_version`，支持单会话/全量撤销。切换后不得因代码回退重新接受已撤销无状态会话。

## 4. API 契约

| Method | Path | 作用 |
|---|---|---|
| GET | `/api/v2/session` | 返回 `unbound/active/stale/unmapped`、当前用户、当前租户、候选租户与 CSRF token |
| GET | `/api/v2/session/tenants` | 返回本人 active memberships 对应的 active tenants 与 CSRF token |
| PUT | `/api/v2/session/tenant` | 提交唯一候选 `tenant_id`；必须带 `X-CSRF-Token` |
| DELETE | `/api/v2/session/tenant` | 清除 tenant 绑定并轮换为新的 unbound scope；必须带 `X-CSRF-Token` |

GET 在 scope 缺失、过期或 stale 时签发新的 unbound scope。零 membership 返回 `200`、空数组和 `unmapped`，不阻断旧系统登录。PUT 对无权 tenant 统一返回 404 `tenant_not_available`，不泄露租户是否存在；请求模型禁止额外字段。所有 Location/下一页均为服务端固定相对路径，本批不接受 `next` 或外部回跳参数。

CSRF token 使用独立 HMAC 域从完整 scope token 派生，只通过 JSON 返回并由客户端放入 `X-CSRF-Token`；绑定或解绑后 scope/session id 和 CSRF 必须一起轮换，其他用户、登录或旧 scope 的 token 均无效。

## 5. 权威授权链

```text
验签 wxsess
→ 验签 wxscope 并比对登录指纹
→ 取得候选 tenant_id
→ 同步服务函数打开 tenant_transaction
→ 同连接校验 enabled user + active tenant + active membership
→ 从数据库取得当前 membership role
→ 执行业务 SQL 并统一 commit/rollback
```

客户端请求体、query、`X-Tenant-ID` 和旧 `team_id` 均不得决定业务租户。平台 `super/admin` 不自动获得任何租户数据。作用域解析 helper 只能用于页面状态/前置提示；未来业务读写必须在同步服务函数中重新进入 `tenant_transaction`，不得在 FastAPI 异步依赖里跨 `await` 持有数据库事务。

## 6. 状态与回退

- `unbound`：已登录但没有选择租户。
- `active`：scope 中候选 tenant 仍对应 active tenant + active membership；返回数据库实时 role。
- `stale`：scope 合法但 membership/tenant 已失效，或 scope 本身非法；清除候选并轮换 unbound scope，旧登录保留。
- `unmapped`：用户没有任何 active membership；旧系统继续可用。

关闭 binding 即可回退；新 Cookie 被旧代码忽略。禁止从 `teams` 名称或旧 `admin/member/super` 自动猜测 tenant/role，也禁止自动选择查询结果的第一条 membership。

## 7. 后续资源审核垂直切片

下一批最小对象为共享 `event_editions`、`tenant_resource_grants`、`tenant_candidates`、`tenant_reviews` 和事务 Outbox；首批只开放 Candidate 列表/详情、开始审核与完成审核。`qualified_leads` 和 `lead_user_state` 不能冒充权威 Review。完成命令必须使用 `Idempotency-Key + expected_version`；在 decision/disposition 字典确认及最小 Opportunity 就绪前，不开放 `sales_handoff`。
