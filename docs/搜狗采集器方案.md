# 搜狗微信采集器 — 定稿方案

> 状态：规划已定稿，待实现。归档时间：2026-08-11。
> 渠道定位：搜狗微信是第二采集渠道（主渠道为 PC 微信搜一搜 UI 自动化，已存档提交 ff235ea）。

## 1. 目标与范围
- 输入：多关键词（少量、高频）+ 时间档（默认**一天内**）。
- 输出：**标题 / 公众号 / 发布时间 / mp 真链 / 正文全文**，写入**现有统一库** `data/wechat_search.db` 的 `articles` 表。
- 渠道标识：`source="sogou_weixin"`（PC 渠道是 `wechat_pc`）。
- 纯桌面 Playwright 无头，无模拟器；**静态代理列表**可选；**内建 `--loop --interval`** 高频循环。

## 2. 技术前提（已验证）
- **桌面 Playwright + Chromium（无头）已完全替代模拟器**，实测多关键词、四档时间筛选、翻页到底、四字段提取全部跑通，经用户人工核对条数一致（`最新网络投票评选通知` 一天内 = 22 条）。
- **MQQBrowser UA 伪装是富页关键**：普通 UA 只给 10 条无筛选裸页；伪装成手机版 MQQBrowser UA 才下发带筛选面板的富页。
  - UA：`Mozilla/5.0 (Linux; U; Android 14; zh-cn;) AppleWebKit/537.36 (KHTML, like Gecko) Version/4.0 Chrome/107.0.0.0 MQQBrowser/13.9 Mobile Safari/537.36`
- **Playwright 反爬配置**：`new_context(user_agent=MQQ_UA, viewport={390,844}, device_scale_factor=3, is_mobile=True, has_touch=True, locale="zh-CN")`；`launch(headless=True, args=["--disable-blink-features=AutomationControlled"])`；`add_init_script` 抹 `navigator.webdriver`。
- **暖会话**：必须先 goto `m.sogou.com` 建会话，再 goto `m.sogou.com/web/searchList.jsp?keyword=X`。
- **weixinwap 翻页是"追加模式"**：结果累加在同一页（第1页10→第2页20→第3页22…），`#next_page` 隐藏=到底。
- **时间筛选面板**：`#select_start`（开面板）→ `span.conditionTime[data-type="N"]`（1=一天内/2=一周内/3=一月内/4=一年内）→ `#select_confirm`（确定）。禁忌：直接 URL 加 `&tsn=` 会被反爬弹回首页。
- **四字段提取**：`li[id^="sogou_vr"]` 内 → h4 a=标题、`.s2[data-sourcename]`=公众号、`.s3[data-lastmodified]`=时间、`a[href*="/link?url="]`=搜狗跳转链（需解析成 mp 真链）。

## 4. 数据模型与跨渠道去重（关键）
- 复用 `Article` / `Database`，**不新建存储**。
- `Article.url` = **解析后的 mp 真链** → `fingerprint()` 用 URL 的 md5 → **PC/搜狗同一篇文章指纹相同，自动跨渠道去重**。
- 三层去重：
  1. 关键词内：按搜狗 href + `标题|公众号`。
  2. 跨关键词（同轮）：入库时 UNIQUE 指纹拦截。
  3. 跨轮次（高频）：**解析真链前先 `exists_by_title_account()` 查库**，已采过的**直接跳过、不解析、不抓正文** → 高频重复跑开销极低。

## 5. 单关键词采集流程
1. 暖会话 `m.sogou.com`（每个 context 每轮一次，复用）
2. `searchList.jsp?keyword=kw` → 点 `#weixin` → `weixinwap`
3. 校验富页（`发布时间` 标志）；缺失 → 判定被反爬 → 退避+重暖+重试
4. 时间筛选：`#select_start` → `span.conditionTime[data-type=时间档]` → `#select_confirm`，等 `networkidle`+延时
5. **追加模式翻页**：点 `#next_page` → 等 DOM li 数**真正增长**再继续，直到 `#next_page` 消失 / 不增长 / 到 `max_pages`（已验证正确逻辑）
6. **增量早停**（高频优化，可配置）：某页新增项若**全部已在库**（按 `标题|公众号`），因结果按时间倒序，判定已触达旧区 → 提前停翻页
7. 逐条：`exists_by_title_account` 命中→跳过；否则 → 解析 mp 真链 →（可选）抓正文 → `db.save()`

## 6. 并发与代理
- 并发数 = `min(concurrency, 代理数)`（无代理时用 `concurrency`，建议单机 2–3）。
- 每 worker = 一个浏览器 context（可绑定各自代理）。关键词进 `asyncio.Queue`，worker 取任务。
- 代理：`proxies: ["http://user:pass@host:port", ...]`，worker i 绑 `proxies[i % n]`；解析成 Playwright `proxy=` 参数。空列表=单机 IP。
- **硬约束**：真正瓶颈是搜狗按 IP 限频。单机 IP 只能温和并发（2–3）+ 随机延时 + 退避；真正大批量高频需代理池，吞吐随 IP 数近似线性放大。

## 7. 高频与增量调度
- `--loop`：进程常驻，每轮跑完 sleep `loop_interval_sec` 再跑；浏览器/会话复用，少暖机。Ctrl+C 优雅退出。
- 默认单次跑；`--loop` 开循环。

## 8. 正文全文抓取
- 解析出 mp 真链后，同 context 打开文章页，抽 `#js_content` 的 innerText，清洗空白 → `content`。
- 抓不到（图片文/已删/验证页）→ `content` 存空，记录仍保留。
- 受 `fetch_content` 开关控制（默认 `true`）。

## 9. mp 真链解析（浏览器内）
- 搜狗 href 是相对 `/link?url=...`，用 `weixin.sogou.com` 补全。
- 新开页 goto 该链 → 等跳到 `mp.weixin.qq.com` → 取最终 URL，规范化（保留 `__biz/mid/idx/sn`，去跟踪参数）。
- 解析失败兜底：存搜狗链，指纹回退 `标题|公众号`。
- ⚠️ **实现第一步先验证**：搜狗 `/link` 在无头浏览器里能否稳定跳到 mp（可能有 JS 跳转/反爬）。若不稳，当场加重试/短延时；这不改变"浏览器内解析"的选型。

## 10. 反爬与容错
- MQQBrowser UA + 手机模拟 + 抹 `navigator.webdriver` + 随机延时（`min/max_delay_sec`）。
- 检测弹回首页/验证码 → 指数退避（`backoff_base_sec`）+ 重暖会话，最多 `max_retries` 次；仍失败则记录并跳过该关键词本轮（不中断整轮，沿用 PC `Collector` 的 per-keyword try/except 风格）。

## 12. 命令行
```
python main_sogou.py                      # 用 config.json 的 sogou 段
python main_sogou.py -k 关键词1 关键词2      # 覆盖关键词
python main_sogou.py -t 1                  # 覆盖时间档(1天/2周/3月/4年)
python main_sogou.py --concurrency 3       # 覆盖并发
python main_sogou.py --loop --interval 600 # 高频常驻循环
python main_sogou.py --headful             # 调试时看浏览器
```
